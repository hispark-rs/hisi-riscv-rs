1//! CPU-generic runtime facade.
2//!
3//! This module is the chip-neutral interface over `riscv-rt`. It should not grow
4//! chip addresses, image-header layout, interrupt names, or board memory maps.
5//! Those facts belong in chip startup adapters and linker fragments.
6
7/// Marks `fn main() -> !` as the firmware entry point.
8///
9/// When control reaches `main()`, the startup adapter has already:
10///
11/// - Initialized shared RAM banks (dynamic memory config)
12/// - Initialized and invalidated L1 caches
13/// - Relocated all sections from flash to RAM (ROM data → DTCM,
14///   TCM text → ITCM, TCM data → DTCM, SRAM text/data → SRAM)
15/// - Zeroed BSS (ROM BSS, TCM BSS, SRAM BSS)
16/// - Enabled the ROM patch table (if non-empty)
17/// - Enabled the FPU (`mstatus.FS = Dirty`)
18/// - Set `mie` bits for TIMER0-2, RTC, I2C0, I2C1
19///
20/// These specifics vary by chip; see the selected chip adapter source module
21/// (for example, `chips::ws63`) for the exact sequence.
22///
23/// # Chip-specific behaviour
24///
25/// See the crate's `chips` source module for chip-specific startup details.
26pub use riscv_rt::entry;
27
28/// Runs a function before [`entry`] — typically for custom early
29/// initialization.
30///
31/// See [`entry`] for the environment that has already been set up by the
32/// time `main()` is reached.
33pub use riscv_rt::pre_init;
