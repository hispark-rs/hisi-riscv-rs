# WS53 IPC 环形队列：格式实现与并发边界

**状态：** 历史配套证据；架构迁移和当前状态见 [实施记录](ws53-adaptation.md)。

当前新增的是独占普通内存上的 SDK 格式队列事务，尚不是与原厂控制核并发运行
的完整 IPC。接收方不能凭本地关中断构造共享区 `&mut [u8]`；门铃 ACK 也不表示
控制核停止访问、释放 buffer 或完成缓存维护。A 板维持原厂应用，本阶段无硬件访问。

`rom/app/drivers/chips/ws53/porting/include/acore/ipc_porting.h`、
`application/ws53/ws53_application/main.c:337`、原生只读 ROM 的
`ipc_set_msg_into_mailbox` / `ipc_get_msg_from_mailbox`。
ROM 输入为上一轮已保存的 `[0x1f220,0x1fa20)`，SHA256
`2c88c7b2090d64db73307fbd45005b27882308443b092fbedc85be63586a662a`。
本阶段只检查既有文件，没有重新读取板卡。原始 ROM 不进入公开证据。

| 偏移 | 大小 | 含义 |
|---|---|---|
| 0/1/2 | 各1字节 | 源核、目的核、channel；应用2、控制0、channel0/1 |
| 3 | 1字节 | empty：1为空，0非空；仅游标相等时决定空/满 |
| 4/6 | 各2字节，小端 | read/write 游标，均严格小于 capacity |
| 8 | 4字节，小端 | capacity = 总区域长度−12 |
| 12 | capacity 字节 | 环形字节数组；消息头和 payload 都可能跨尾 |

消息为 ID/priority 各1字节、length 两字节小端和内联 payload。Rust 将 ID 限于
0..18、priority0/1、payload≤60；不沿用 ROM 未检查长度/ID 的回调索引。
此前观察到的总区域0x500/0x100对应 capacity1268/244，只是当前配置，不能
把地址、内存归属、缓存属性或安全区交接固定为芯片通用默认值。

## empty 的竞态为何尚未关闭

ROM 生产者在 `0x1f5b8` 发布 write 游标，再在 `0x1f5ba–0x1f5c0` 条件清 empty；
消费者在 `0x1f67c` 发布 read，在 `0x1f67e–0x1f684` 比较 write/read，随后
`0x1f68a` 写 empty=1。双方都写该字节。本地 IRQ 锁不互斥两个 CPU。

一个顺序一致的反例：容量244，初始有64字节消息，read=0、write=64、empty=0。
生产者先预留新64字节消息；消费者读完旧消息，发布read=64并观察write=64，
但暂未写 empty。生产者连续发布64、64、64、52字节，恰好把244字节装满，
write再次等于64；各次检查 empty 仍为0。消费者最后依据旧比较写 empty=1。
此时游标相等且标为空，但实际有244字节未消费。后续发送可能错误地认为空间可用。

脚本检查既有 ROM 中15处精确指令，15处字节变异逐项拒绝；对容量8的两次发送
和容量244的四次发送，枚举保持双方操作顺序的2268个有限交错（含留一字节变体），
得到64个双方发布完成后仍满却标空的原协议反例。初版判据还计入20个最终恢复
正确的临时发布窗口，复核后已排除并加入定向负控制；暂时看到相等游标不足以
证明丢数据/唤醒。容量1268另有具体20次发送反例。跨核真正互斥的三个整事务
顺序没有该反例。读字段被分组，模型没有穷尽各条指令、cache/总线弱序或所有容量。

这只证明一种**允许的协议交错**，没有测到硅片上发生该竞态，也没有证明当前
控制核所有补丁路径与应用核 ROM 相同。不能据此诊断板卡损坏。生产者始终留
至少一字节在本次有限场景消除了反例，但尚无证据证明保留的厂商生产者遵守此
约束；不能静默换成 Rust 自定协议，再宣称兼容未修改的控制核。

## 已实现与待验收

`MailboxSize`验证可表达的范围16..65548字节（capacity4..65536），不是板级
分配器；`Route`区分两个核心方向与两路channel。`MailboxImage`只借用独占
普通内存，初始化仅写12字节元数据，attach不写。push先检查剩余空间，再写
内容和提交游标；pop先复制到本地最多64字节、验证完整消息，再提交读游标和
调用者输出。损坏队列保持原样，交由上层明确恢复；不自动跳过、清空或执行 ID。

主机用例覆盖111264个消息/容量/跨边界组合、每种过长u16声明、未知ID/
priority、元数据错误、guard/tail不变、20000步独立FIFO对照。QEMU运行真正
生产Rust事务，虚拟对端独立解析队列并交接图像；CPU和对端严格轮流访问，三轮
启动/复位分别核对完整图像及输出哈希：发送309条、接收303条、57次拒绝均
不消费。这里没有声称运行完整厂商控制核模型。有效但错误的empty值本身不能
通过格式校验检出，独占图像层也不能修复之前并发造成的内容丢失。

下一步仍需核对控制核实际 ring/补丁路径与缓存属性，建立兼容的实时发布和
满/空协议、通知重试与 drain/rearm、不丢唤醒、所有权交接及复位恢复，再接入
共享资源服务。`MailboxImage`不能代替这些步骤。IPC 的并发传输、服务协商、
低功耗、RAM 实板、Flash 实板、真正断电冷启动和逻辑分析仪验收均保持未完成。
