# WS53 IPC 分层迁移状态

目前正在迁移，不是完整通信栈。既有 RAM/QEMU 证据对应旧源码与旧交接契约，不能
自动证明迁移后的行为或实际控制核固件兼容性。本轮不操作硬件。

| 原实现 | 目标职责 | 当前状态 |
| --- | --- | --- |
| HAL `ipc_ws53.rs` 的 doorbell、通道和 IRQ | HAL 的硬件通知、使能、状态和确认 | 保留；不证明队列、固件协议或资源交接 |
| HAL `MessageId`、`Message` | 控制核组件的明确固件协议 | 编解码及测试、现有调用者已迁移；HAL 旧实现已删除 |
| HAL `mailbox`、`layout` | 厂商格式和经配置的布局 | 原实现、测试和现有调用者已迁移；HAL 旧实现已删除，布局不能当作实际固件自动识别 |
| HAL `spsc` | 实验性 WS53 共享队列传输 | 原算法、并发测试及现有模型调用者已迁移，HAL 旧实现已删除；新增仅轮询端点适配，通知仍由平台负责，不能默认用于不明固件 |
| HAL `random_buffer` | 控制核服务，独立随机来源 | 两个调用者已迁移；HAL 服务已删除。服务使用回调保留错误及暂存语义，仍不拥有活跃共享区 |
| HAL 硬件、平台启动和应用 | 物理所有权、缓存及启动交接 | 保留原 unsafe 前提；不因迁移引入虚构握手或将单核临界区当跨核锁 |

`hisi-ws53-coex` 目前是独立仓库和父仓子模块中的未发布原型，依赖仅有
`vcell` 和可选 `defmt`，无 PAC/HAL 依赖。它提供通用有界端点契约、本地显式
失效包装、仅用于主机测试的单槽实现及实验性 WS53 轮询队列适配。短接收缓冲区保留消息并报告所需长度；
发布结果不确定时不能盲目重试。失效不会自动检测对端复位，也不会回收共享区。
异步等待、通知唤醒和取消尚未实现。`Sdk163d9150` 只是显式选择的源码
配置标识，轮询适配构造要求指定它，但不能自动识别实际控制核固件。

`5a8971a` 起，完整但格式非法的帧报告 `InvalidMessage`，不推进游标，
也不自动重置队列；元数据异常、游标异常或已发布长度不足报告 `Corrupt`，
并使会话永久失效。长度不足无法区分损坏帧和违反完整发布规则的对端，因此
保守视为传输状态损坏。恢复元数据不会恢复旧会话；平台仍须独立证明对端
静止、缓存与内存所有权，不能用这种错误分类推断对端复位已经被可靠检测。

迁移顺序：梳理源模块、调用方和证据；迁移厂商协议及其测试；接入符合安全前提
的 WS53 通知与会话；最后处理独立组件发布、
外部消费者、QEMU 对端和实板复验。旧 SPSC 发布要求逐消息授权远端地址及服务，
轮询适配要求由平台实现带安全契约的逐消息授权策略；共享区域、缓存及对端
静止的前提仍由 unsafe 接入承担，不能将授权策略本身当作缓存或所有权证明。
既有资料与 SHA 索引保留在原 evidence 记录，禁止把模型测试误称为实板通过。

分层后重新编译并执行的四组 QEMU 结果、报告位置与校验值见
[软件验证记录](evidence/ws53-ipc-layering-2026-10-29.md)。新轮询端点后来通过
独立 QEMU 并发与失效测试；真实对端、通知竞争和非一致性缓存仍未验收。
