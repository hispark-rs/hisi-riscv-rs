## Implementation

Backend `60faf85b7ce47c1c3f8a93f604c911785d3d671b` tracks type-4
`frw_host_post_data`, actual `frw_netbuf_exec_callback` execution and
pre-dispatch `oal_netbuf_free`. The original post can return zero after enqueue
failure, so its return is not accepted as a drain receipt. Non-reused tickets
allow an address to be reallocated before the old callback/post stack returns.
Retirement requires both the post return and completed dispatch or free.

Requested deauthentication closes admission and waits at most 1000 ms for
tracked host work before entering WAL. Native calls and waits run outside
critical sections. Missing clock, sleep error, timeout and ownership failures
fail closed. The 32 slots own no packet data and cost **576 additional bytes**
in the final RV32 `.data` section. This is reported separately from L2 storage.

Ordinary TX can use a direct HMAC fast path; EAPOL uses queue 4. Queue-4
counts therefore do not equal application UDP counts. Dispatch completion
does not mean DMAC completion or an over-the-air receipt. Autonomous native
deletion closes admission without waiting inside its callback. These limits
are part of the [implementation contract at the tested source](https://github.com/hispark-rs/hisi-rf-ws63/blob/60faf85b7ce47c1c3f8a93f604c911785d3d671b/docs/net0-host-tx.md).
