# WS63 RF A2 Storage/NVS Evidence (2026-07-13)

## Scope

This evidence covers the A2 migration from the RF-local WS63 ACPU KV parser to
independent `hisi-storage` and `hisi-nvs` release units, plus relocation of the
WS63 radio NV partition linker contract out of `hisi-riscv-rt`.

## Ownership Result

- `hisi-storage 0.1.0-alpha.1` provides bounded memory-mapped/read-only
  `embedded-storage` access and is published on crates.io.
- `hisi-nvs 0.1.0-alpha.1` owns the ACPU KV page/key/CRC/sequence parser and nine
  adversarial host tests. Its source/tag/CI are complete; crates.io publication
  is pending organization-secret access for the new repository.
- `ws63-rf-rs::uapi_nv_read` now only adapts the vendor C ABI to
  `NvReader<MemoryMappedStorage>` and keeps RF-owned key IDs.
- `ws63-radio-sys/linker/ws63-nvs.x` owns the current WS63 radio NV partition
  symbols. `hisi-riscv-rt/linker/ws63/memory.x` no longer contains NVS policy.

The final ELF resolves:

```text
00004000 A __nv_storage_length
005fc000 A __nv_storage_start
```

## Host And Link Evidence

- `hisi-nvs`: 9/9 unit tests pass, including complement/CRC corruption,
  duplicate sequence selection, equal-sequence physical ordering, corrupt-prefix
  recovery and integrity-before-`BufferTooSmall`.
- Parent workspace check and clippy pass on `riscv32imfc-unknown-none-elf`.
- Guarded RF link verifies 1,486 layout sections, 5,335 vendor relocations and
  37 mask-ROM patches.
- Final ELF SHA-256:
  `3b99d8a7c41eda7abc1c474261252e1953e6b70db2323df909fe9faee942f978`.
- Planned image SHA-256:
  `c54a3338aa836b0f79f9fe82b075f327d4566bd612638e1cefd3198a69eb8042`.
- Moving the linker symbols from RT to `ws63-radio-sys` produced a byte-identical
  planned image (`cmp` passed), so the ownership change did not alter flash data.

## WS63 HIL

The planned bin was downloaded with probe-rs, booted through J-Link nRST, and
captured on UART0 at 115200 baud. The third reset produced the complete baseline:

```text
RF1_IMAGE_OK
RF2_INIT_OK ifname=wlan0 ... hwlen=0x00000006 mac=<redacted>
RF3_SCAN_OK count=0x0000001f
RF5B_WPA_CONNECT_OK freq=0x0000096c
RF5A_DHCP_OK addr=192.168.155.2 prefix=0x00000018 router=192.168.155.1
RF5A_ARP_OK rx=0x00000004
RF5C_PING_OK rx=0x00000005
```

Two preceding resets reached init/scan and then reported vendor association
`0x1451`; the identical third-run image completed connect/DHCP/ARP/ping. This is
recorded as radio-environment variance, not hidden as deterministic success.

The test credential was injected at build time and is not part of the evidence
artifact.
