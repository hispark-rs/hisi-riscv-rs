# WS63 RF A1 ROM Metadata Migration - 2026-07-13

## Scope

This evidence records moving generated mask-ROM facts into the independent
`hisi-rom-sys 0.1.0-alpha.2` release unit. The language-neutral source remains
`ws63-RF/rom`; parent CI compares that pinned source with the generated crate
artifacts.

## Boundary

- `hisi-rom-sys` packages 3,752 ROM symbol assignments, 227 ordered callback
  targets and 37 mandatory Wi-Fi patch names with source SHA-256 values.
- Release artifacts contain normalized machine facts only; vendor source
  commentary remains in `ws63-RF`. `0.1.0-alpha.2` supersedes the initial
  unnormalized extraction.
- Cargo `links = "hisi_rom_sys"` metadata gives downstream build scripts stable
  artifact paths. `wifi_init_smoke` no longer reaches laterally into
  `crates/ws63-radio-sys/ws63-RF/rom` for symbols or callbacks.
- The final application still chooses `PROVIDE` fallback policy.
- `hisi-riscv-rt` still owns the patch controller and fixed table layout.
- The transitional RF post-link script still creates patch payloads against the
  final ELF; that mechanism moves later with `hisi-rf-link`.

## Silicon Parity

The image was transferred at 115200 baud with the explicit loaderboot, followed
by a physical J-Link reset. Credentials were injected through the environment
and are not recorded here.

```text
RF1_IMAGE_OK
RF2_INIT_BEGIN
RF3_SCAN_OK
RF5B_WPA_CONNECT_OK freq=0x0000096c
RF5A_DHCP_OK addr=192.168.155.2 prefix=0x00000018 router=192.168.155.1
RF5A_ARP_OK rx=0x00000003
RF5C_PING_OK rx=0x00000004
```

The final marker proves the ROM metadata ownership migration preserved the
complete WPA2 and Rust-visible L2 path on real WS63 silicon.
