# NET0 Native RX Stop Experiment (2026-09-09)

Status: **terminal stop implemented; 3/3 preflight passed; the requested
20-reset stopped at 2/3. NET0/reconnect remains open.** No release or broader
support claim follows from these results.

## Exact Implementation

Backend `06d790bfe7d9016f7be44f42601b5afa567b9111` adds the default-off
`standard-l2-rx-stop-experiment`. After tracked host TX drain and checked user
cleanup, a one-shot request uses native device message 91. Registration checks
the original handler, replaces only that handler, and forwards unrelated
native invocations. A correlated receipt requires enqueue return and actual
handler return, the expected device-worker identity, MAC disabled and empty
software RX descriptor lists. Queueing or an outer zero result alone cannot
pass. Errors and timeout keep the route closed; there is no reopen capability.

Six standard RV32 LUI/ADDI/JR veneers resolve the pinned ROM symbols correctly
without numeric production addresses. The linked gate decodes ten call sites
and six veneer targets; all sixteen mutations are rejected. The receipt owns
32 bytes, no packet storage. Full `OsalTask.task` generation-tagged identity is
compared to the runtime handle, not to the slot-only OSAL pid/tid. The observed
matching device-task handle is `0x105`.

Details and limits belong to the [backend contract at the tested source](https://github.com/hispark-rs/hisi-rf-ws63/blob/06d790bfe7d9016f7be44f42601b5afa567b9111/docs/net0-rx-stop.md).
In particular, software descriptor counts are not DMA-idle status; this does
not yet fence message 595, every native callback or autonomous re-enable.

has diagnostic stage `disconnect`; user cleanup was not observed for an
associated user. The original trigger before authorization is not attributed
to the AP or RF hardware. A successful terminal receipt cannot establish
recovery, and repeating this matrix until lucky success would not close that
gap. Its original failed outcome is retained.
