# WS63 RF A1 Hardware Crypto Backend - 2026-07-13

## Scope

This evidence records the split between chip-neutral crypto capabilities and
the WS63 cipher/TRNG UAPI backend. It proves the current WPA2 hardware path; it
does not claim SHA/HMAC/AES accelerator support, TLS support, or a stable API.

## Boundary

- `hisi-crypto 0.1.0-alpha.3` commit
  `48c12bb737efd65b8f97e0b611b1f628e2041fba` adds small fallible
  `Pbkdf2HmacSha1`, `TryHash`, `TryMac`, `TryBlockCipher`, `EntropySource` and
  explicit `CryptoSuite` contracts. The monolithic provider is legacy-only.
- `hisi-crypto-ws63 0.1.0-alpha.1` commit
  `82d758ccd5faac50cdc6a8092af89c2b76c817e9` owns the WS63 PBKDF2/TRNG
  FFI, ABI layout, iteration bounds and backend errors.
- RF explicitly selects one unsafe-exclusive `Ws63Crypto` for PBKDF2/TRNG and
  `RustCryptoProvider` for SHA/HMAC/AES. Hardware failure never selects the
  software path.
- The backend exposes neither TLS nor supplicant C ABI. Those remain protocol
  adapters above the primitive layer.

The new repository CI and package verification pass. Its first crates.io
publish workflow lacked access to the organization `CRATES_IO_TOKEN`; the tag
exists, but publication remains an explicit release follow-up rather than being
misreported as complete.
