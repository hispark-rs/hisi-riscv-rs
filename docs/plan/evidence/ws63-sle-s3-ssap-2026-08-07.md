# WS63 SLE S3 SSAP Evidence

## Scope

This evidence closes S3: two WS63 boards complete SLE connect, SSAP exchange,
primary-service discovery, property read, server-originated notification, and
client-initiated disconnect through bounded copied events. It does not claim
pairing, authenticated SSAP, client write, coexistence, or a stable public SLE
API.

## Diagnostic History

An intermediate image made pairing a prerequisite for SSAP. Every reset then
failed before SSAP with vendor status `0x8000600c` (`ERRCODE_SLE_AUTH_FAIL`).
Both boards reported 152 entropy bytes, seven entropy requests, and zero entropy
failures, so that result did not indicate a TRNG outage. Pairing was removed
from the S3 critical path because it is a separate security and product-UX
milestone, not because the authentication failure was silently accepted.

This scope correction also removed client write from the S3 pass gate. The
write ABI remains experimental; this evidence proves discovery, read, and
notification only.

## Silicon Result

Board A ran the server image and board B ran the client image. Each image was
downloaded once with full verify. A 3/3 shape gate and the final 20/20 matrix
then used only the two J-Link nRST lines while capturing both UART streams.

Every final run contained:

```text
RFDBG_SLE_S1_INIT_OK
RFDBG_SLE_S3_SERVER_SERVICE_OK
RFDBG_SLE_S3_SERVER_READY
RFDBG_SLE_S3_SERVER_CONNECTED
RFDBG_SLE_S3_SERVER_NOTIFY_OK
RFDBG_SLE_S3_SERVER_DISCONNECTED
RFDBG_SLE_S3_CLIENT_CONNECTED
RFDBG_SLE_S3_CLIENT_LINK_READY
RFDBG_SLE_S3_CLIENT_EXCHANGE_OK
RFDBG_SLE_S3_CLIENT_SERVICE_OK
RFDBG_SLE_S3_CLIENT_READ_OK
RFDBG_SLE_S3_CLIENT_DATA_OK
RFDBG_SLE_S3_DATA_DISCONNECT_OK
```

All 20 records report empty missing-marker and failure-marker sets. Client logs
were 856 bytes each and server logs were 792 bytes each, providing an additional
guard against a marker-only partial lifecycle. The executable evidence contract
is `hil/ws63-sle-ssap-reset-matrix.py`. Raw UART logs and `summary.json` remain
under `/private/tmp/ws63-sle-s3-20260807/{3reset-v13,20reset-v13}` on the HIL
host.

## Boundary

This is integration and statistical regression evidence for two fixed images,
two boards, and the stated environment. It validates the bounded S3 lifecycle
and callback ownership. It is not a mathematical RTOS proof and does not prove
pairing, write, security, future RF environments, or external peers can never
lose events.
