`unstable` 时，DMA 正例导入私有模块，产生 E0603。已有子仓独立脚本主要验证
实验配置，未覆盖该组合。此次保持 DMA 运行时行为、可见性与安全前提不变。

HAL `f39aef7`（[草稿 PR #27](https://github.com/hispark-rs/hisi-hal/pull/27)，叠加 #26）：

  不再允许 E0603 私有模块错误充当所有权/安全测试通过的依据。
- 原 token 所有权正例继续在实验配置编译；WS53 的独立 MDMA 实现未修改。
- 独立脚本新增稳定 WS63、稳定 WS63 async 两组测试与 Clippy。三个 private timer
  辅助函数仅在未启用 `unstable` 时允许不可达告警，与既有私有包装器的行为一致；
  实验配置依然以 `-D warnings` 检查，无算法或寄存器访问变化。

故障敏感性：隔离副本只将首个 E0521 预期改为 E0133，nightly rustdoc 报告
“缺少预期错误码”，八个反例中恰有一个失败。故障没有进入发布源码。
初版把超时恢复错误写成 E0599，也被检查拒绝；核对 `unsafe into_parts` 后改为
正确的 E0133。原失败日志全部保留。

本机原版默认文档测试没有收集到远端失败的正例（仅两个反例），包括尝试显式
文档 cfg 后仍如此；因此**不宣称本机已复现完整的远端收集行为**。远端原始错误
是修复前证据，本机修改后矩阵与诊断故障注入是不同证据，远端关闭待新 CI 确认。
