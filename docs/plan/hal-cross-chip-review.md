# HAL 跨芯片结构审查与分批计划

**状态：** WS53 适配的配套工作，分批实施中。

基线：HAL `ab697df` 附近的 WS53 实验分支。此表是整改队列，不代表相同名称的
IP 或驱动语义已被证明相同；每批合并前仍需对照 PAC、SDK、测试和现有硅片证据。
WS63/BS2X 公开接口保持兼容，WS53 仅在 `unstable` 下调整。父仓承载跨仓 QEMU
及实板，纯逻辑、feature、门控和驱动测试由 HAL 子仓负责。

| 模块 | 当前差异与边界 | 下一步 |
| --- | --- | --- |
| GPIO / pinctrl | WS53 区分 bank、pad、共享 GPIO1 时钟与既有交接；WS63 GPIO 资源和寄存器布局不同 | 对照标准 digital trait、状态与错误；复用相同逻辑，pad/时钟配置留在 SoC，保留不同寄存器后端 |
| UART | `uart.rs` 已含共用部分，`uart_ws53.rs` 是 WS53 接收/trait 实现；H0、复位及 pad 特定 | 先核对可共用 FIFO/trait 逻辑，H0/实例/IRQ 留 SoC 或行为后端，不能改变既有 WS63 API |
| DMA | WS53 v151 MDMA 八槽、保留资源和缓存交接；WS63 DMA/SDMA 通道及寄存器不同 | 先共用边界计算和取消状态机的可证明部分；请求路由归 SoC，独立后端保留停机与缓存差异 |
| TIMER | WS53 两通道 v150；WS63 三定时器，接管与 IRQ 不同 | 比较通用 tick/超时与 async 逻辑；寄存器和时钟后端分离 |
| TCXO | WS53 应用窗口含多片段快照；WS63 计数器快照路径不同 | 审查快照/超时通用算术，保留窗口及时钟语义差异 |
| Embassy | WS53 当前独立队列与资源交接，旧后端使用现有队列工具；状态、重试及唤醒语义须对齐 | 优先审查共用调度核心和后端最小能力；先用各芯片测试证明，不简单替换队列 |
| I2C | WS53 v151、BS2X DesignWare v151、WS63 v150；同号不等于行为相同 | WS53/BS21 共用字节事务规划，但寄存器、资源与失败处理保持独立；BS21 中止分类有 SDK/主机证据，超时恢复和实板仍未证实，实例/时钟/路由继续归 SoC |
| SPI / QSPI | WS53 v151_100、WS63 SSI v151；FIFO、复位、CS、资源交接尚未完全等价 | 先比对配置、帧处理和 trait 适配；不同 IP/行为保留独立后端，不能转换 PAC 寄存器类型 |
| I2S | 同称 v151 但 WS53 的 FIFO 与传输完成契约独立核对 | 比较配置边界与数据打包；外设请求/IRQ 放 SoC，完成语义保留各自证据 |
| PWM | WS53 255 tick 配置及组通道，与 WS63 16-bit 期望不同 | 仅共用已证明的分频/参数运算，保留宽度、时钟和停止行为差异 |
| RTC | WS53 v150 应用 32-bit profile；BS2X v150 64-bit，WS63 v100 | 对照计数器、握手及宽度，保留不同后端；只共享可证实的参数/等待逻辑 |
| WDT | WS53 v151 与 WS63 位宽、NMI、时钟/接管可能不同 | 比较超时计算和命令序列；保留 NMI、复位与不可恢复边界 |
| ADC / LSADC / GADC | WS53 v155，WS63 v154，BS2X v153；校准/诊断共享资源不同 | 保留各 IP 后端，按相同行为抽取纯数值转换；不得套用其他芯片寄存器 |
| TRNG | WS53 统一安全域及已配置交接，WS63/BS2X 有各自实现；IPC18 服务已移出 HAL | 审核有界读取/错误与熵接口，保留独立域、时钟与 FIFO 语义 |
| 温度 | WS53 原始码与启动/完成证据有限，WS63 实现不同 | 共用经证实的纯转换；停止/IRQ 未证明不补空实现 |
| eFuse | WS53 仅受限只读服务，WS63 有不同 v151 控制及接口 | 保留只读安全边界与不同后端；不可引入写入、OTP 或虚构清除 |
| SFC | WS53 受交接约束的 CPU 命令读取，WS63 Flash 控制不同 | 保留只读与 XIP/控制核约束；先抽取边界校验，Flash 写入不可由其他芯片推定 |
| SDIO | WS53 设备侧和现有其他芯片能力不等价 | 暂保留独立后端；共享通用缓冲/状态计算前先核对真实对端 |
| HASH / SYMC / KM | WS53 低层硬件及保留资源契约；WS63 使用 `hisi-crypto` 与 `hisi-crypto-ws63` | 低层寄存器/独占保留 HAL，算法 provider 和资源策略沿现有加密分层；先验证语义与缓冲生命周期 |
| IPC / 控制域 | HAL 硬件 doorbell、芯片复位/时钟是平台能力；消息、邮箱和 IPC18 是固件协议 | 协作层迁移进行中；硬件与协议依赖方向单向，不能把固定 SDK 版本误当对端识别 |
| pin/IRQ/clock/request 配置 | `soc/ws53` 已有 pin 类型，其他配置仍散落各驱动与 `lib.rs` | 按每批驱动抽到 `soc`；只集中已有证据，不补猜测 |
| 非 WS53 其他外设 | USB、PDM、KEYSCAN、QDEC、无线等是各芯片独有或尚未证实 | 保持现有模块和接口，不因统一结构增加不存在的 WS53 能力 |

首批复用：HAL `6fa9738` 将 WS53、WS63/BS21 的整数时钟/时长换算集中到
`timer_math`，分别保留原有零值、溢出返回和饱和规则；三芯片相关主机测试及
目标架构 Clippy 通过。此批不改变 timer 寄存器、时钟配置或硬件行为。

DMA 后续审查发现旧 WS63/BS21 guard 的超时取消、可遗忘的借用和缓存行
所有权存在未关闭的内存安全问题；先按 `docs/plan/legacy-dma-safety-audit.md`
核实并修正，暂不合并其取消状态机，也不宣称旧 guard 已证明安全。

第二批：HAL `fba0a1f` 共用当时的 TCXO 四段计数拼装；保留原始寄存器位、
WS53 掩码字段、各自读取顺序及快照状态机。后续已发现 WS63 的四段假设错误，
见下方修复。三芯片 TCXO 主机测试
和 RISC-V Clippy 通过；测试使用集成依赖覆盖，不能当作独立发布验收，也未新增实板验证。

第三批：HAL `a3163e8` 共用 Embassy 硬件计数与有限宽度定时器分段运算，
修复 WS63/BS21 的大计数和远期截止时间乘法溢出；WS53 保留原有的过期、
重试和饱和策略。三个后端的队列、唤醒、IRQ 和资源交接仍独立：既有 WS63/BS21
使用的 `u64::MAX` 空队列哨兵也未改变。三芯片主机边界测试与 RISC-V Clippy、
WS53 QEMU Embassy 场景通过，WS63/BS21 行为变更尚未在对应实板验收。

第四批：HAL `81d4ada` 依据 WS63 SDK 的 `CONFIG_TCXO_WITH_TWO_DATA_REGS`
修正 TCXO 和 Embassy 读取：WS63 用两组 32 位寄存器，BS21 保持四组读取。
旧 WS63 PAC 的四组 16 位描述与该 SDK 配置不一致，当前 HAL 使用兼容的原始
32 位访问器；SVD `9f11980` 和 PAC `6324bcf` 的草稿 PR 已修正描述并添加完整
字读取，旧访问器保留，两项均尚未合并或发布。三个芯片
主机测试、目标 Clippy 和 WS63 QEMU 普通计数范围冒烟通过；高位组合有主机
寄存器视图测试，长运行、真实板卡和上电时序未验收。

第五批：HAL `2777409` 将 WS53 的方向切换、空操作和最终 STOP 规划独立为
可复用的命令规划器；`96ad17e` 将其接入 BS21 v151，修复原有
`transaction`/`write_read` 在各操作间插入 STOP 的行为，并使探测超时返回
false。WS53 保持其原有控制器状态机和恢复契约。主机测试覆盖两后端命令序列、
空操作、超时、NACK 和 STOP 同时到达中止；WS53 数字 QEMU 虚拟对端重新通过
57 段线序。BS21 当前 QEMU 模型不区分重复 START/STOP，不是该项验证证据；
当时所有 TX 中止仍归为 NACK（见下方后续修复），超时后总线是否空闲和恢复方式均未证实，不能继承
旧实板验收。此批没有操作硬件。

第六批：HAL `90b1981` 按 BS2X SDK 的中止来源在清除前采样，区分 NACK、
仲裁丢失和保留原始位的其他/混合中止，避免错误地全部报告 NACK；`probe`
仍为布尔接口，无法细分失败。BS21 全部 208 项主机单测、三芯片目标 Clippy
与 BS21 QEMU 普通收发/NACK 冒烟通过；该模型不证明仲裁、重复 START 波形、
超时后的控制器或外部总线恢复，实板尚未验证。

第七批：HAL `cd9bbec` 共用三芯片 UART 的 1/64 分频计算；WS53 仍按 SDK
选择 8/16 倍采样，WS63/BS21 保持 16 倍及原寄存器操作。WS53 SDK 配置表、
三芯片 UART 主机测试与 RISC-V Clippy 通过；WS53 UART 时钟门控 QEMU 六组
通过，但模型使用预设字符时长，不能证明波特率。测试脚本已纳入版本管理，
远端检出及隔离 Cargo 缓存重建夹具后通过；固定模型源码另从远端检出，
使用本地上游镜像全新构建 QEMU 后复验通过。变更后的实板尚未复验。
另外发现旧芯片 `BaudRate::try_new` 只按 PLL 基准校验，`UartClock::Boot`
实际频率较低时允许配置的整数分频可能为零（例如 24 MHz、3 Mbaud）；
现有无错误返回构造器保持兼容，该边界需设计可报告错误的配置接口并核实
芯片实际行为，不能把测试通过视为 Boot 时钟全范围安全。

后续 HAL `3adeac4` 为 WS63/BS21 添加可报告分频错误的 `try_new_uartN`；
所选时钟分频不合法时返回原 token，且不写 UART 寄存器；Boot 档会读取芯片
时钟配置，不能证明实际时钟频率。旧 `new_uartN` 保持兼容且仍不校验，调用方
须迁移到新接口才获得检查。主机边界测试覆盖 24/40 MHz、高波特率、上下限和
失败不调用配置操作；三芯片目标 Clippy、相关单测以及两旧芯片文档构建通过，
新接口尚未进行实板波形验证。

实施顺序：继续完成 IPC 独立依赖和未覆盖的传输语义，再选取可证明相同的纯计算及 Embassy
调度内核建立首批共享实现；随后按 timer/TCXO、GPIO、UART、I2C/SPI、DMA 和
复杂外设依次审查。每批单独提交与验证，保留有理由的独立后端；不会以文件数量
减少代替代码复用、行为等价、安全审计或真机验收。

I2C 共享规划器验证：HAL `5f14c4a` 对 WS53/BS21 各生成 2048 组含空操作、
重复方向与方向切换的序列，核对字节顺序、重启和最终停止；两芯片规划器测试
通过。各芯片现有 I2C 主机测试分别通过 WS53 26 项、BS21 25 项、WS63 11 项。
WS63 没有使用该规划器；此次未改变驱动行为，使用父仓集成依赖，不能替代独立
发布构建、虚拟线序或实板波形验收。

GPIO trait 共享：HAL `8ca6fd8` 统一 WS53、WS63/BS21 的 `embedded-hal` 输入、输出和状态查询转发，保留各自的 pin 类型、寄存器、资源与 Drop 行为。共享测试以独立输入/输出状态核对 trait 调用；三芯片 GPIO 相关主机测试分别 10、32、28 项及 RISC-V Clippy 通过。WS53 固定远端依赖的独立预发布检查通过；未做硬件测试，接口转发合并不代表不同 GPIO 后端行为已统一。

BS21 中止分类后续修正：HAL `7b47884` 修复仲裁位与其他原因同时出现时丢弃原始字的问题；仅单独仲裁及 SDK 规定的从机伴随位组合归类为仲裁丢失，其他混合原因保留完整原始值。相关三芯片回归通过，混合中止仍未做 QEMU 或实板验证。

I2C v151 后续：HAL `6644031` 将 BS21 与 WS53 确认相同的中止详情位分类共用，WS53 的独立 source 字与各后端寄存器行为保持隔离；同时修正 WS53 通用呼叫未应答的地址 NACK 分类。后续 QEMU 已针对 bit4 注入并验证驱动恢复，实板仍未验收；模型和 CI 证据以 [WS53 适配进度记录](ws53-adaptation.md) 为准。

SPI 帧处理：HAL `d210f6a` 共用两类后端的逐帧填零、接收和丢弃逻辑，寄存器和错误恢复仍各自独立。旧 WS63/BS21 后端固定为全双工，却在 `write` 中未读走接收 FIFO；现在每帧等待并丢弃接收值，避免将残留数据带入后续传输。WS53 正常数字线序模型通过，旧芯片实板尚未验收；SDK 配置事实及完整测试边界见 [实施记录](ws53-adaptation.md)。

旧芯片模型补充：WS63 和 BS21 的合成回环 FIFO 各运行长写后短读，HAL `20f5a7f` 均复现旧数据，`d210f6a` 均返回正确的新数据。模型 FIFO 深度和实际电气时序不构成实板证据；WS63 示例位于独立子仓的 [草稿 PR](https://github.com/hispark-rs/ws63-examples/pull/6)。

SPI 分频共用：HAL `44b74dc` 按各芯片声明的输入频率计算不超过请求值的最小偶数分频。WS53 原先已有此规则，旧 WS63/BS21 以前向下取整可能超速，例如假设 160 MHz 输入时 30 MHz 请求得到 40 MHz；现在选择分频 6，约 26.67 MHz。接口不变，但非整除频率的输出会改变，实际源时钟与物理波形仍需实板确认。
